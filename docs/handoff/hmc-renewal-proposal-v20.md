**対象:** [humanmarketcap.com](https://humanmarketcap.com/)  
**作成日:** 2026年8月13日  
**作成:** Manus AI

## 結論

Human Market Capは、現行の「診断フォーム」から、個人の将来収益力を読む**分析デスク**へ進化させるべきです。デザインの軸はBloomberg Terminalの複製ではなく、暗い作業面、高い情報密度、等幅数字、更新を示す色、比較可能なモジュールという考え方を取り入れた、独自の **HMC Market Desk** です。これにより、「診断を受ける」体験ではなく「自分の人的資本を分析する」体験に変えられます。

算定では、現在の年収を将来収益の唯一の起点にしないことが重要です。各職業に「実収平均年収」とは明確に区別した **ポテンシャル年収アンカー** を置き、可搬性、スキルの資本化、副収入、キャリア後半の継続収入を加えます。公開されているv19モデルの60職業を基に再設定した結果、年収ゼロの職業を除く単純平均は **414.4万円から577.7万円へ39.4%上昇**し、中央値は **350万円から500万円**になります。[2]

> **提案の原則:** 数字を高く見せるのではなく、「将来の収益可能性を含むポテンシャル評価」として高く、かつ説明可能に出す。実収年収や採用市場の客観価格を主張しない。

| 判断項目 | 推奨判断 | 期待する効果 |
|---|---|---|
| ブランド | `HMC Market Desk` を独立した名称として採用 | Bloombergとの誤認を避けながら、金融分析の緊張感を持たせる |
| 主画面 | 入力フォームではなく「HMC Quote」を先頭に置く | 結果の見栄え、共有性、再訪価値を高める |
| スコア名称 | 「人間時価総額」＋「将来収益ポテンシャル評価」を併記 | エンタメ性と説明責任を両立する |
| 職業値 | 基準年収を「ポテンシャル年収」へ置換 | 標準的な入力でも結果を上方へ再配分する |
| 不確実性 | Base / Upside / Resilience の3シナリオを同時表示 | 高い数字を恣意的に見せず、納得感を上げる |

## 1. 現行サイトの診断

現行サイトは、黒背景・金色のアクセント・セリフ体の見出しによって、高級感と金融商品のような雰囲気をすでに備えています。ユーザーは「基本情報」「キャリア」「資産・投資」「金融クイズ」の4ステップを進み、給与所得、資産所得、初期資産を合算するDCF的な査定を受けます。[1] 一方で、第一印象が入力フォームに寄りすぎており、最も価値があるはずの「結果を読む」「他のキャリアと比較する」「どの要因が効いたかを理解する」体験が前面に出ていません。

公開されているv19のモデル定義には60職業の基準年収、就労終了年齢、賃金カーブ、職業別のキャリアリスクと移行所得率が含まれます。例えば、職業の基準年収は上場企業一般社員400万円、ITエンジニア450万円、医師900万円、AIエンジニア600万円として置かれています。[2] これは職業ごとの違いを表現するには有効ですが、現在の年収入力との関係、将来の再現可能な上振れ、キャリア後半の収益化がユーザーに十分見えません。

| 現行の強み | 改修で解消すべき点 | リニューアル時の扱い |
|---|---|---|
| 4ステップで情報を集めるため、診断の物語性がある | フォーム中に評価結果の手掛かりが少なく、離脱しやすい | 各ステップの右側に「暫定HMC」「変動理由」「次に増える価値」を常時表示する |
| DCF、資産、金融リテラシーという差別化された題材 | 実際の計算前提が見えにくい | 結果に「Calculation Trace」を設置し、寄与額と計算期間を開示する |
| 金・黒の世界観がすでにある | 金の使用量が多いと、重要度の差が弱くなる | 金はブランドと基準値に限定し、上振れ・リスクは別色で表す |
| 職業ごとのキャリア曲線を持つ | 基準年収が“平均年収”に読め、低く感じる職種がある | 「ポテンシャル年収アンカー」と明示し、能力の資本化を別項目にする |

## 2. HMC Market Desk のUI方針

### 2.1 デザイン言語

Bloombergらしさは、オレンジ色や画面の模写ではなく、**数値を主役にする規律**にあります。HMCでは、ブランド名、ロゴ、ショートカット体系、特定の画面構成を模倣せず、独自の情報システムとして設計します。高密度な画面ではすべてを一度に出すのではなく、最重要指標を最初に示してから分析詳細を開く段階的開示が適切です。NN/gも、初期画面では重要な選択肢だけを示し、専門的・低頻度の情報を要求時に開示することで、学習しやすさ、効率、誤りの低減を図る原則を示しています。[3]

| レイヤー | 役割 | デスクトップでの表現 | モバイルでの表現 |
|---|---|---|---|
| Global Bar | 状態と移動 | `HMC // MARKET DESK`、匿名ID、更新日時、再計算 | 1行の固定バー、通知はドロワーへ |
| Quote Header | 最重要の結論 | 大きな時価総額、前回比、Tier、信頼レンジ | 数字、Tier、主要因を縦積み |
| Driver Tape | 価値変動の理由 | `+ Career Option`、`+ Asset Compounding`、`− Career Risk` を横並び | 横スクロールのチップ |
| Analytics Grid | 深掘り | 年収曲線、資産曲線、寄与度、職業比較を2列グリッド | 1カードずつスワイプまたはタブ切替 |
| Calculation Trace | 透明性 | 前提・係数・年度別PVを展開表示 | 「算定根拠を見る」の詳細シート |

### 2.2 推奨レイアウト

最初に表示するのは入力画面ではなく、**HMC Quote**です。未入力の初回訪問者にはサンプル数値を薄く見せ、中央の「あなたのHMCを発行する」ボタンで入力を開始させます。診断後は同じ場所が本人の結果に切り替わるため、再訪時の価値が生まれます。

### 2.3 色、文字、状態のルール

データ可視化では、少数の一貫した色セットを定め、データ用の色、非データ用のグレー、アクセント色を役割ごとに分けると運用と理解が安定します。[5] HMCでは、金をすべての強調に使わず、「HMCの基準値」と「重要なCTA」に絞ります。上振れと下振れは色だけに依存せず、`UP` / `RISK` のラベル、矢印、線種を併用します。

| トークン | 推奨値 | 用途 |
|---|---|---|
| Desk Black | `#0B0D10` | 背景。真っ黒ではなく長時間閲覧で白文字が刺さりすぎない濃紺黒 |
| Panel | `#151A20` | カード、表、入力面 |
| Grid | `#2A323B` | 罫線、軸、非アクティブ領域 |
| HMC Gold | `#F6B94E` | 時価総額、Tier、主CTA、基準線 |
| Growth Cyan | `#62D8FF` | 収益上振れ、キャリアオプション、主系列 |
| Compound Green | `#8FE3A6` | 資産運用・再投資の寄与 |
| Risk Red | `#FF7A7A` | 下振れ要因、未確定性、警告 |
| Text / Numbers | `Noto Sans JP` + `DM Mono` 相当 | 本文は可読性、数値・単位・時刻は等幅で比較可能にする |

## 3. 算定ロジック v20: Opportunity-Adjusted Human Capital

### 3.1 表示する価値の定義を変える

v20の中心は「額面年収を現在から将来に延長する」考え方ではなく、**現在の収入、職種ごとの収益能力、保有資産、将来の選択肢**を分けて計上することです。これにより、現時点の年収が低い若手、転職直後、独立初期、ライフイベント中の人でも、過度に低い結果になりません。

> **HMC Base:** 現在の観測収入だけでなく、現職・保有スキルから再現可能とみなせる将来収益力を現在価値へ換算した、教育・エンターテインメント目的の試算値。

次の4要素を独立表示します。

\[
\mathrm{HMC}_{Base}=A_0+PV(\mathrm{Core\ Income})+PV(\mathrm{Career\ Option})+PV(\mathrm{Asset\ Income})
\]

| 要素 | v20の定義 | 高めに出すための正当な設計 |
|---|---|---|
| 初期資産 \(A_0\) | 金融資産、不動産、その他資産を流動性別に時価評価 | 不動産・事業資産を一律に低く扱わず、流動性係数を明示する |
| Core Income | 現在年収と職種のポテンシャル年収のうち、説明可能な高い方を基点にした将来所得 | `max(入力年収, ポテンシャル年収 × 0.85)` を下限にする |
| Career Option | スキルの転用、昇格、副業、顧問・講師・監修・印税などの選択肢価値 | 職業特性に応じて本体所得の8〜22%を別建てで計上する |
| Asset Income | 再投資・利回り・保有期間による資産の寄与 | Baseケースは過度なハイリスク利回りに依存せず、資産クラス別に表示する |

職業別の「ポテンシャル年収アンカー」は、公的な賃金統計を下限確認の材料にしながら、実収平均ではなく、専門性・可搬性・副収入可能性を含む評価用数値として定義します。厚生労働省の令和6年賃金構造基本統計調査は、学歴別、産業別、雇用形態別、勤続年数別、役職別などの賃金統計と表を公表しており、職業パラメータをレビューする際の外部アンカーとして利用できます。[4]

### 3.2 年度別の計算式

ユーザーが結果画面で確認できる程度に、以下の式を簡潔に開示します。バックエンドでは年度ごとの明細を計算し、画面では合計と主要な寄与だけをまず示します。

\[
I_t=\max\left(Y_0\times C_{job,t},\;B_{job}\times0.85\times C_{potential,t}\right)\times M_{skill}\times M_{mobility}
\]

\[
PV(\mathrm{Core\ Income})=\sum_{t=1}^{T}\frac{I_t\times R_t}{(1+d_t)^t}
\]

\[
PV(\mathrm{Career\ Option})=\sum_{t=1}^{T}\frac{I_t\times O_{job}\times Q_{user,t}}{(1+d_t)^t}
\]

| 記号 | 意味 | Baseケースの設計値 |
|---|---|---|
| \(Y_0\) | 入力された現在年収 | そのまま尊重する。入力値を勝手に下げない |
| \(B_{job}\) | 職業別ポテンシャル年収アンカー | 60職業ごとに再設定。全体平均を+39.4%上方へ移す |
| \(C_{job,t}\) | 職業固有の年齢別収益カーブ | ピーク前は昇格・専門化、ピーク後は顧問・教育・管理職の継続収入を反映 |
| \(M_{skill}\) | スキルの証明係数 | 資格、管理経験、作品、継続学習。0.98〜1.12の範囲 |
| \(M_{mobility}\) | 市場可搬性係数 | 転職・副業・地域・リモート適性。0.98〜1.10の範囲 |
| \(R_t\) | 継続確率 | Baseでは急激な失職を主シナリオに入れず、Downsideで強く反映 |
| \(O_{job}\) | キャリアオプション率 | 安定職8〜12%、専門職12〜16%、独立・コンテンツ職16〜22% |
| \(d_t\) | 割引率 | Baseは年4.5〜6.5%。職業リスクを一括で二重控除しない |

### 3.3 「高く出す」ために変えるべき3点

第一に、**現在年収だけを起点にしない**ことです。たとえば若手AIエンジニア、独立直後の会計士、管理職昇格前の上場企業社員は、現時点の給与だけで将来を評価すると低く出ます。v20はポテンシャル年収アンカーの85%を収入下限に置くため、職業に内在する再現可能な収益力を反映できます。

第二に、**キャリア後半をゼロにしない**ことです。現役ピークを過ぎた後も、管理、教育、顧問、監修、ライセンス、事業承継などの形で収入が続く職業は多くあります。ただし全職業の終業年齢を一律に引き上げるのではなく、「主たる職業収入の終了」と「拡張キャリア収入の終了」を分けます。アスリートやプロゲーマーは主戦場のピークを早く置きつつ、指導・解説・スポンサー・コミュニティ運営の移行カーブを別に持たせます。

第三に、**Base / Upside / Resilienceを併置する**ことです。もっとも大きい数字だけを固定表示すると信頼を損ねます。初期表示はBaseを最も大きくし、すぐ隣に「Upside（成長・副収入が実現）」と「Resilience（保守的な継続性）」を置けば、Baseを従来より高く設計しても、恣意性ではなくシナリオ差として説明できます。

| シナリオ | 位置づけ | 画面での扱い |
|---|---|---|
| Base | 最も起こりやすい将来収益ポテンシャル | 大きなHMC Quoteとして初期表示 |
| Upside | 役職昇格、独立成功、知的資産化、副収入が進んだ場合 | 金色/シアンの上向き帯で表示 |
| Resilience | キャリア中断、収益鈍化、流動性低下を反映 | 赤だけに頼らず、点線と`RESILIENCE`ラベルで表示 |

### 3.4 入力項目の見直し

現行の学歴・容姿補正は、数字の面白さはある一方で、ユーザーが「能力ではなく属性を査定された」と感じるリスクがあります。v20では容姿を主係数から外し、希望者だけが選べる「対人・発信・営業チャネル」へ置き換えることを推奨します。学歴も固定的な序列ではなく、資格・専門訓練・研究実績・ポートフォリオを含む「スキル証明」に再編します。これは結果を下げる変更ではありません。むしろ、非学歴の専門スキルや経験を加点できるため、より多くのユーザーに上方余地を提供できます。

| 現行の見方 | v20の入力・表示 | 結果への影響 |
|---|---|---|
| 最終学歴 | スキル証明（学位、資格、作品、実務専門性） | 一律の学校序列ではなく、0〜4個の証明で最大+12% |
| 容姿 | 対人・発信・営業チャネル（任意） | 職種と関連する場合のみ、オプション価値へ最大+5% |
| 転職 | 市場可搬性・副業可能性 | リスク控除だけでなく、収益機会として最大+10% |
| 金融クイズ | 資産運用の実行度 | 利回りを直接盛りすぎず、再投資継続率に反映 |

| 高スキルフリーランス | 350万円 | 500万円 | 単価改善、契約の複線化、講師・監修 | 主収入73歳 |
| プロスポーツ選手 | 400万円 | 600万円 | 現役の希少性、スポンサー、指導・解説への移行 | 現役45歳、拡張キャリアへ移行 |
| YouTuber・配信者・VTuber | 200万円 | 300万円 | コンテンツ資産、広告以外の収益化 | 主収入65歳、リスクはDownsideで反映 |
| 専業主婦・主夫 | 350万円 | 500万円 | 家事労働の市場代替価値、家計運営スキル | 主収入80歳 |

### 職業パラメータの運用ルール

職業別の数値は固定値のまま放置せず、年1回更新するデータ運用にします。公開モデルの各職業にはすでに基準年収や年齢カーブがあるため、v20ではこのデータ構造を維持しつつ、`potentialIncome`、`primaryEndAge`、`extensionIncomeRate`、`optionRate`、`skillPortability` を明示的な項目として追加します。[2] 新しい職業を加える際も、これらの項目を必須にすれば、恣意的な高評価を避けながら「高いが説明可能」な結果になります。

## 5. 結果画面の情報設計

結果ページでは、最初の1画面でユーザーが「自分は高く評価された」「何が効いたか」「次に何をすれば上がるか」を理解できる必要があります。そこで、巨大な総額だけで終わらず、寄与度と行動可能性を横に置きます。

| モジュール | 最初に出す内容 | 展開後に出す内容 |
|---|---|---|
| HMC Quote | 総額、Tier、前回比、Baseレンジ | 3シナリオの前提差、更新履歴 |
| Value Drivers | 上位3つの加点、最大の下振れ要因 | 年度ごとの寄与、係数、改善条件 |
| Income Curve | 収入のピーク年齢、ピーク年収、累計PV | 年齢ごとの給与・副収入・顧問収入 |
| Asset Engine | 初期資産、再投資、運用益の割合 | 資産クラス別利回り・流動性調整 |
| Profession Scanner | 同職種のポテンシャルレンジ、上位職種との差 | 職業を変えずに上がる要因、隣接職種への移行シナリオ |
| Calculation Trace | 4つのPV合計 | 式、割引率、期間、すべての年度行 |

ユーザーに見せる言葉も、評価の温度を上げます。たとえば「あなたの価値」だけでは漠然とするため、以下のように金融端末らしいが独自のラベルを用います。

| 場所 | 推奨コピー |
|---|---|
| ヒーロー | `PRICE YOUR FUTURE EARNING POWER` |
| 総額ラベル | `HMC QUOTE / BASE CASE` |
| 前回比 | `CHANGE SINCE LAST VALUATION` |
| 加点 | `UPSIDE DRIVERS` |
| リスク | `RESILIENCE CHECK` |
| 計算詳細 | `CALCULATION TRACE` |
| 行動提案 | `NEXT VALUE CREATOR` |

## 6. 実装優先順位と検証

まずUIだけをBloomberg風にしても、結果の納得感がなければ共有されません。したがって、実装は「v20データ仕様と結果画面」を同じ優先度で作るべきです。職業値をフロントエンドに固定せず、バージョン付きのモデル定義としてサーバー側に置くと、後から更新、A/Bテスト、説明表示が容易になります。

| 優先度 | 実装項目 | 完了条件 |
|---|---|---|
| P0 | v20評価仕様、60職業CSV、シナリオ設計 | 代表的な12ペルソナで、総額・内訳・上昇要因が説明できる |
| P0 | HMC QuoteとCalculation Trace | 1画面目で総額・レンジ・上位3ドライバーが読める |
| P1 | Market Desk UI、Professional Scanner | デスクトップ/モバイルで表、チャート、職業比較が崩れない |
| P1 | スキル証明・市場可搬性の新入力 | 学歴・容姿依存を減らし、経験者にも上方余地を提供できる |
| P2 | 更新履歴、前回比、共有画像 | 再訪・SNS共有で“成長の物語”が生まれる |
| P2 | 職業パラメータの年次レビュー画面 | モデルのバージョンと更新理由を公開できる |

検証では、現在の数値をただ引き上げたかだけでなく、ユーザーが納得できるかを確認します。12ペルソナは、若手会社員、管理職、医療職、IT職、非正規雇用、独立初期、経営者、資産家、クリエイター、アスリート、夜職、無業を含めます。各ペルソナでBaseが現行より上がること、Upsideが単なる誇張でなく具体的な前提と紐付くこと、Resilienceが必要以上に人格評価にならないことを受け入れ条件にします。

## 7. ガバナンスと表示上の注意

このサービスの魅力は強い言葉と数字にありますが、職業、学歴、容姿、収入を扱うため、結果が個人の尊厳を損なわない設計が不可欠です。総額の直下には、次の短い説明を常時置くことを推奨します。

> この数値は、入力情報とモデル前提に基づく将来収益ポテンシャルの試算です。実際の収入、雇用可能性、金融商品の価値、人格的価値を示すものではありません。

また、メソドロジー画面には、職業別の値が「観測された平均給与」ではなく、何を含むポテンシャル年収なのかを明記します。これにより、数字を高めに設定しても、誤認を招く“客観的な相場”のようには扱わず、サービス独自の評価モデルとして持続できます。
